# 07 — النشر

## Render (مخطّط جاهز)

`render.yaml` في جذر المستودع ينشئ خدمتين: تطبيق Next.js وقاعدة PostgreSQL مربوطة به.

1. في Render: **New → Blueprint**، واختر مستودع `bawsalati` وفرع `main`.
2. ستطلب منك Render قيمة `SEED_PASSWORD` — اكتب كلمة مرور قوية (10 محارف فأكثر).
   هي كلمة مرور الحسابين الأوّلين: `admin@bawsalati.om` و`naeem@bawsalati.om`.
3. اترك بقية المتغيّرات كما هي. `JWT_SECRET` تولّده Render، و`DATABASE_URL` يُربط تلقائياً.
4. **Apply**. البناء يطبّق الترحيلات ثم يهيّئ بيانات المقياس ثم يبني التطبيق.

بعد أول نشر ناجح: سجّل الدخول بحساب المدير، وغيّر كلمة المرور من صفحة المختصين،
ثم ارفع دليل الطالب من `/admin/guide`.

### ما يجري في البناء

```
npm ci → prisma generate → prisma migrate deploy → npm run seed → next build
```

`prisma migrate deploy` و`npm run seed` آمنان عند التكرار: الترحيلات المطبَّقة لا تُعاد،
والتهيئة تستخدم `upsert` فلا تكرّر بيانات ولا تُعيد ضبط كلمة مرور حساب قائم.

## قيود الخطة المجانية

| القيد | الأثر | الحل |
|---|---|---|
| القرص مؤقّت | ملفات المكتبة ودليل الطالب تختفي عند كل نشر | ترقية الخدمة، ثم إزالة التعليق عن كتلة `disk` في `render.yaml` وضبط `STORAGE_DIR` على `/var/data` |
| الخدمة تنام عند الخمول | أول طلب بعد فترة سكون يستغرق نحو دقيقة | ترقية الخدمة |
| قاعدة البيانات المجانية تنتهي بعد 30 يوماً | فقدان البيانات | ترقية القاعدة قبل انتهاء المدة |

`embedded-postgres` أداة تطوير محلية فقط، لكنها تُنزّل ثنائيات PostgreSQL أثناء `npm ci`
فتضيف نحو دقيقة لكل بناء. إن أزعجك ذلك، احذفها من `devDependencies` واستخدم PostgreSQL
مثبّتة محلياً بدلاً من `npm run db`.

## قائمة ما قبل النشر

- [ ] `SEED_PASSWORD` مضبوط، والتهيئة لا تعمل بدونه في الإنتاج.
- [ ] `JWT_SECRET` مولّد ولا يساوي قيمة التطوير.
- [ ] تغيير كلمات مرور الحسابين الأوّلين بعد أول دخول.
- [ ] قرص دائم مربوط قبل رفع أي ملف مكتبة أو دليل يُعتمد عليه.
- [ ] `NOTIFY_PROVIDER` مضبوط على مزوّد حقيقي، وبياناته في متغيّرات البيئة لا في الشيفرة.
- [ ] نسخ احتياطي دوري لقاعدة البيانات ولمجلد التخزين معاً.
- [ ] مراجعة `/admin` بعد النشر: لا تحذيرات معلّقة في لوحة الحالة.

## متغيّرات البيئة في الإنتاج

| المتغيّر | المصدر |
|---|---|
| `DATABASE_URL` | من قاعدة البيانات تلقائياً |
| `JWT_SECRET` | تولّده منصة الاستضافة |
| `SEED_PASSWORD` | تُدخله يدوياً مرة واحدة |
| `STORAGE_DIR` | مسار القرص الدائم |
| `NOTIFY_*` | من مزوّد الإشعارات |
| `APP_URL` | اختياري — يُشتق تلقائياً من `RENDER_EXTERNAL_URL` |

## استضافة أخرى

المشروع خادم Node عادي، فيعمل على أي منصة تدعم Next.js وPostgreSQL بالخطوات نفسها:
`npm ci` ثم `prisma migrate deploy` ثم `npm run seed` ثم `npm run build`، وتشغيل `npm start`.
الشرط الوحيد الإضافي هو قرص دائم لمجلد `STORAGE_DIR`، أو استبدال `src/lib/storage.ts`
بتخزين كائنات إن رغبت لاحقاً.

## رسائل واتساب

بعد كل حجز تصل رسالتان: قصيرة إلى رقم المختص، وكاملة التفاصيل إلى
`BOOKING_ALERT_PHONE`. الطريق يحدّده `NOTIFY_PROVIDER`:

| القيمة | متى تُستعمل | ما يلزم |
|---|---|---|
| `callmebot` | تنبيه أرقام معروفة كالإدارة والمختصين، مجاناً | كل رقم مستلم يفعّل الخدمة بنفسه ويأخذ مفتاحه، ثم يُضاف إلى `CALLMEBOT_KEYS` |
| `whatsapp-cloud` | الواتساب الرسمي من Meta | رقم أعمال، و`WHATSAPP_TOKEN` و`WHATSAPP_PHONE_NUMBER_ID`، وقالب معتمد في `WHATSAPP_TEMPLATE` |
| `console` | التطوير | يسجّل في السجلّ ولا يرسل |

**تفعيل CallMeBot للرقم 94996269:** من ذلك الهاتف نفسه تُضاف جهة الاتصال التي
تذكرها صفحة الخدمة الرسمية في callmebot.com، وتُرسل إليها عبارة التفعيل. يصل
المفتاح برسالة، ثم يُضاف في لوحة Render:

```
CALLMEBOT_KEYS=96894996269:<المفتاح>
```

والرسالة تمرّ بخادم CallMeBot وفيها اسم الطالب ورقمه، فهي خدمة طرف ثالث.
للاستعمال الرسمي الدائم فالأسلم `whatsapp-cloud`.

**واتساب Meta:** النصّ الحرّ لا يصل إلا لرقم راسل رقم المنصة خلال آخر 24 ساعة.
لإرسال مضمون في كل وقت يُعتمد في Meta قالبٌ بمتغيّر واحد `{{1}}` ويُكتب اسمه في
`WHATSAPP_TEMPLATE`، فيُرسل نصّ الحجز فيه مفصولة أسطره بـ« | ».

حالة كل رسالة (أُرسلت، فشلت، تُخطّيت وسببها) مسجّلة في جدول `notification_deliveries`.
